# M3 — CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add GitHub Actions CI that runs `stack build`, `stack test`, and `hlint` on every push and PR-to-main across an Ubuntu + macOS matrix, with a status badge on the README.

**Architecture:** One workflow file (`.github/workflows/ci.yml`) with two parallel jobs: `build-and-test` (matrix over `ubuntu-latest` + `macos-latest` × GHC 9.6.6) and `lint` (Ubuntu-only — hlint is OS-independent). `haskell-actions/setup@v2` installs the toolchain; `actions/cache@v4` persists `~/.stack` and `.stack-work` keyed on `stack.yaml.lock` + `package.yaml`. `haskell-actions/hlint-setup@v2` + `hlint-run@v2` handles the lint step with PR annotations. Before any CI exists, the codebase's existing 4 hlint hints are fixed so the first CI run is green.

**Tech stack:** GitHub Actions, `haskell-actions/setup@v2`, `actions/cache@v4`, `actions/checkout@v4`, `haskell-actions/hlint-setup@v2`, `haskell-actions/hlint-run@v2`. Local `hlint` v3.10 (already installed via `brew install hlint` during plan writing).

## Task 2 — Add build-and-test workflow

**Files:**
- Create: `.github/workflows/ci.yml`

- [ ] **Step 2.1: Verify the `.github/workflows/` directory does not exist yet**

```

```

Expected: `No such file or directory`. If something already exists under `.github/`, stop and report — Task 2 assumes a clean slate.

- [ ] **Step 2.2: Create `.github/workflows/ci.yml`**

```
mkdir -p /Users/dodofk/Misc/opencode-hs/.github/workflows
```

Write the file content below to `/Users/dodofk/Misc/opencode-hs/.github/workflows/ci.yml`. Note: hlint is added in Task 3 — this task ships build-and-test only so each commit lands one logical change.

```yaml
name: CI

on:
  push:
    branches: ['**']
  pull_request:
    branches: [main]

permissions:
  contents: read

jobs:
  build-and-test:
    name: ${{ matrix.os }} / GHC ${{ matrix.ghc }}
    runs-on: ${{ matrix.os }}
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, macos-latest]
        ghc: ['9.6.6']
    steps:
      - uses: actions/checkout@v4

      - name: Set up GHC and Stack
        id: setup
        uses: haskell-actions/setup@v2
        with:
          ghc-version: ${{ matrix.ghc }}
          enable-stack: true
          stack-version: 'latest'

      - name: Cache Stack global
        uses: actions/cache@v4
        with:
          path: ${{ steps.setup.outputs.stack-root }}
          key: ${{ runner.os }}-stack-global-ghc${{ matrix.ghc }}-${{ hashFiles('stack.yaml.lock', 'package.yaml') }}
          restore-keys: |
            ${{ runner.os }}-stack-global-ghc${{ matrix.ghc }}-

      - name: Cache .stack-work
        uses: actions/cache@v4
        with:
          path: .stack-work
          key: ${{ runner.os }}-stack-work-ghc${{ matrix.ghc }}-${{ hashFiles('stack.yaml.lock', 'package.yaml', 'src/**/*.hs', 'app/**/*.hs', 'test/**/*.hs') }}
          restore-keys: |
            ${{ runner.os }}-stack-work-ghc${{ matrix.ghc }}-

      - name: Build (deps + project, including test deps)
        run: stack build --test --bench --only-dependencies --no-run-tests --no-run-benchmarks

      - name: Build project
        run: stack build --test --bench --no-run-tests --no-run-benchmarks

      - name: Test
        run: stack test
```

Notes on the YAML:
- The `Build (deps)` and `Build project` split ensures the cache step between them is meaningful: dependencies are heavy and rarely change; project code changes per commit.
- `--bench --no-run-benchmarks` keeps the spec-compliant build flags even though we don't have benchmarks yet.
- `fail-fast: false` lets you see results from both OSes even if one fails.

## Task 3 — Add hlint job

**Files:**

- [ ] **Step 3.1: Add a second job `lint` to the workflow**

Open `.github/workflows/ci.yml`. After the existing `build-and-test` job (i.e., append at the bottom of the `jobs:` section), add a sibling job:

```yaml
  lint:
    name: hlint
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Set up hlint
        uses: haskell-actions/hlint-setup@v2
        with:
          version: '3.10'

      - name: Run hlint
        uses: haskell-actions/hlint-run@v2
        with:
          path: '["src/", "app/", "test/", "verify/"]'
          fail-on: warning
```

The full `ci.yml` file should now have two top-level jobs under `jobs:`: `build-and-test` and `lint`. They run in parallel.

Rationale for Ubuntu-only on lint: hlint is OS-independent and only reads `.hs` files. Running it on macOS too doubles the cost for zero additional signal.

## Cost note

The macOS runner in GHA consumes minutes ~10× faster than the Ubuntu runner. For a personal solo project this can add up. If billing becomes a concern post-M3, drop the matrix to `os: [ubuntu-latest]` only. The M3 spec mandates both for the milestone; you can tighten later.
